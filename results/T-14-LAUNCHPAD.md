## Known limitations and tradeoffs (recorded, not hidden)

- **Single shared root `tsconfig.json`** with `"lib": ["ES2022","DOM","DOM.Iterable"]`, rather
  than a stricter per-package split. This means an accidental `window`/`document` reference
  inside `packages/core` would no longer be caught by `tsc` — only at actual Node runtime (e.g.
  during `vitest run` for core, where those globals are genuinely undefined). Chose this because
  the task doc's deliverable table lists `tsconfig.json` as one root artifact and `npm run
  typecheck` is specified as a single command "across every workspace." Full reasoning in
  `notes/T-14-LAUNCHPAD/log.md`.
- **CI's parity/solvability steps soft-skip (warn + exit 0) until a matching `*.test.ts` file
  exists at the documented path**, then run for real as an unconditional hard gate with no
  further changes needed. Chose this over an unconditional hard-fail because the latter would
  redden every unrelated PR (e.g. T-08's) simply because T-01/T-03 haven't merged yet, which
  contradicts README.md's "thirteen of the fourteen tasks can start immediately." Verified live
  against the actual concurrent repo state for both steps (see `notes/T-14-LAUNCHPAD/log.md`): the
  parity step found and correctly ran T-01's real (self-skipping) suite the moment it landed at
  the documented path. The solvability step still soft-skips as of the latest snapshot — not
  because nothing exists, but because what T-03 landed
  (`packages/core/test/level/solvability/run.test.ts`) is at a different path than
  INTERFACES.md/`tasks/T-03-ATLAS.md` document (`packages/core/test/solvability/**`, one level up).
  See the "Path discrepancy" note under "Verification" above — did not special-case my script
  around T-03's actual path; coded against the documented interface, flagged the mismatch for

- **`api/package.json` dependency choices are a proposal, not a negotiated agreement** —
